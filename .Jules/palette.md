## 2026-05-08 - [Interactive States for Physical Device Operations]
**Learning:** In applications that bridge a UI to physical hardware (like connecting to or syncing biometric devices), operations can take significantly longer than standard database calls. Relying solely on separate text status fields (e.g., a "Status: connecting" label) is insufficient UX. Users often interact directly with the trigger element multiple times if there is no immediate, inline feedback.
**Action:** Always apply immediate `disabled` and `aria-busy` states directly to the action buttons (Connect, Disconnect, Sync) that trigger hardware or long-running lifecycle operations. Use a `finally` block to guarantee the UI unlocks regardless of the operation's success or failure.
